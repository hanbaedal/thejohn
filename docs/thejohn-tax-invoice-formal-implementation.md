# 더존(thejohn) 정식 전자세금계산서 구현 가이드

## 1. 문서 목적

본 문서는 더존(thejohn) 홈페이지 **영업관리 → 세금계산서 발부** 기능을, 현재의 **참고용 PDF 양식**에서 **법적 효력이 있는 정식 전자세금계산서 발행**으로 확장하기 위한 구현 순서와 설계 방향을 정리한 것입니다.

수정·보완은 추후 요청에 따라 반영합니다.

---

## 2. 현재 상태와 목표

### 2.1 현재 구현 (참고용)

| 항목 | 내용 |
|------|------|
| 화면 | `tax-invoice.html` — 기간 조회 → 업체 목록 → 상세 모달 |
| 데이터 | 매출장(주문 `sales_records` + 수기 `sales_ledgers`) 기간·업체별 집계 |
| 출력 | `server/lib/taxInvoicePdf.js` — 간이 PDF (국세청 미연동) |
| API | `GET /api/tax-invoices/vendors`, `POST /preview`, `POST /pdf` |
| 한계 | **세무상 정식 발급 아님**, 승인번호·국세청 전송 없음 |

### 2.2 목표 (정식)

- **전자세금계산서 ASP** 또는 국세청 체계를 통해 **승인번호가 부여되는 발행**
- 발행 이력 DB 저장, 중복 발행 방지, 취소·재조회
- 화면: 모달에서 **발행 전 검토** / **발행 후 승인번호·정식 PDF**
- 별도 메뉴: **세금계산서 발행 내역**

---

## 3. 정식 발급의 전제 (코딩 전 결정)

### 3.1 반드시 정할 사항

1. **공급자(발행 사업자)**  
   - (주)더존 단일인지, 관리자(사업자)별인지

2. **발행 단위**  
   - **A안**: 업체 + 조회 기간 합산 1장 (현재 방식)  
   - **B안**: 거래명세서 1건(주문 또는 수기) = 세금계산서 1장 (실무에서 흔함)

3. **연동 방식** (택 1 또는 단계적 도입)

| 방식 | 설명 | 정식 여부 |
|------|------|-----------|
| ASP API 연동 | 바로빌, 팝빌, 더존 Smart A 등 | ○ 정식 발급 |
| 홈택스 보조 | 엑셀/XML 다운로드 후 수동 발행 | △ 시스템 완료까지는 X |
| PDF 양식만 개선 | 겉모양만 유사 | × 정식 아님 |

4. **ASP 계약**  
   - 테스트/운영 API 키, 요금, 발행 건수, 이메일 전송, 취소 가능 기간

### 3.2 법적·업무 참고

- 정식 **전자세금계산서**는 국세청 승인번호가 있어야 합니다.
- 현재 PDF 하단 문구: *「전자세금계산서 국세청 연동 없이 매출장 기준으로 출력한 양식」* — 정식 전환 후에는 발행 경로에 따라 문구를 구분해야 합니다.

## 4. 구현 순서 (권장)

### 0단계: 사전 준비

- [ ] ASP 업체 선정 및 계약
- [ ] 테스트 API 키·인증서(필요 시) 발급
- [ ] 발행 단위(A안/B안) 확정
- [ ] 담당자·권한(관리자/슈퍼바이저) 운영 규칙 확정

### 1단계: 필수 데이터 정비

**공급자·공급받는자 필수 항목**

| 구분 | 항목 |
|------|------|
| 공급자 | 사업자번호, 상호, 대표자, 주소, 업태, 종목, 이메일 |
| 공급받는자 | 사업자번호, 상호, 대표자, 주소, 업태, 종목, 이메일 |
| 품목 | 품명, 수량, 단가, 공급가액, 세액, 과세 구분 |

**작업**

- [ ] `vendors`, `staff` 컬렉션 필드 보완
- [ ] 발행 전 검증 규칙 정의 (사업자번호 10자리, 이메일 필수 등)
- [ ] 업체 등록/수정 화면에서 세금계산서 발행용 필드 입력 유도

### 2단계: DB 설계 (발행 이력)

매출장 조회만으로는 부족합니다. **발행 건**을 별도 저장합니다.

**예: 컬렉션 `tax_invoices`**

```
id
issuerStaffLoginId
vendorCompany, buyerBizNo
periodFrom, periodTo
items[]                    // 발행 시점 품목 스냅샷
supplyAmount, taxAmount, totalAmount
status                     // draft | submitted | issued | cancelled | failed
aspProvider, aspDocId, ntsConfirmNum   // 승인번호
sourceType                 // period_aggregate | order | manual_ledger
sourceIds[]
issuedAt, cancelledAt
createdBy, errorMessage
```

**작업**

- [ ] 스키마·인덱스 정의
- [ ] 중복 발행 방지 (동일 업체·기간·소스 + status=issued)
- [ ] 발행 후 금액·품목 스냅샷 고정 (매출장 변경과 무관)

### 3단계: 서버 — ASP 연동 모듈

**신규 디렉터리 예시**

```
server/lib/taxInvoiceAsp/
  popbill.js      (선택한 ASP)
  mapRequest.js   // 내부 payload → ASP 요청
  issue, cancel, getStatus, downloadPdf
```

**기존 파일 역할**

| 파일 | 정식 전환 후 |
|------|----------------|
| `taxInvoiceBuild.js` | 초안·검증·ASP 요청 body 생성 |
| `taxInvoicePdf.js` | 참고용 PDF (유지) 또는 ASP 정식 PDF 프록시 |
| `routes/taxInvoices.js` | API 확장 |

**신규 API (예시)**

| 메서드 | 경로 | 역할 |
|--------|------|------|
| POST | `/api/tax-invoices/draft` | 초안 생성·검증 |
| POST | `/api/tax-invoices/issue` | ASP 발행 |
| GET | `/api/tax-invoices` | 발행 내역 목록 |
| GET | `/api/tax-invoices/:id` | 상세·승인번호 |
| POST | `/api/tax-invoices/:id/cancel` | 발행 취소 |
| GET | `/api/tax-invoices/:id/pdf` | 정식 발행 PDF |

기존 `POST /preview`, `POST /pdf`는 **참고용**으로 유지하거나 경로명을 `reference-pdf` 등으로 구분합니다.

### 4단계: 발행 비즈니스 로직

1. 매출장(주문 + 수기) 조회 → 품목 집계 (`taxInvoiceBuild.js` 활용)
2. 공급자·공급받는자 조회
3. 필수값 검증
4. `draft` 저장
5. 사용자 「발행」 → ASP API 호출
6. 성공: `issued` + 승인번호 저장
7. 실패: `failed` + 오류 메시지

**세액**: 합계 역산(1.1) vs 품목별 계산 — ASP 규격에 맞출 것.

### 5단계: 화면(UI) — 모달 버튼

현재 흐름 유지: **기간 조회 → 업체 목록 → 모달**

#### 발행 전 (초안)

- 표: 공급자 / 공급받는자 / 품목 / 합계 (`tax-invoice.js` `renderPreviewBody`)
- 누락 필드 경고
- 버튼:
  - **전자세금계산서 발행** (주요)
  - **참고 PDF** (기존)
  - 닫기

#### 발행 후 (완료)

- 승인번호, 작성일, 전송 상태 표시
- 버튼:
  - **정식 PDF 보기**
  - **승인번호 복사**
  - **발행 취소** (가능 시에만)

`taxPdfActions()`를 `draftActions()` / `issuedActions()`로 상태별 분리합니다.

### 6단계: 발행 내역 메뉴

- 신규 페이지: `tax-invoice-list.html` (가칭)
- 영업관리 헤더·허브 링크 추가
- 목록: 기간, 업체, 상태, 승인번호, 금액
- 상세: 재출력, 취소

### 7단계: 권한·감사

- 발행/취소: `admin`, `supervisor` (기존 `taxInvoices` 라우트와 동일)
- 슈퍼바이저: 공급 관리자 선택 유지
- 발행·취소 audit 로그

### 8단계: 테스트

- [ ] ASP 테스트 환경 발행
- [ ] 승인번호 수신
- [ ] ASP/홈택스 포털에서 조회
- [ ] 중복 발행 차단, 취소, 오류(잘못된 사업자번호)
- [ ] 매출장 금액과 발행 금액 일치

### 9단계: 운영 배포

- [ ] 운영 API 키·환경변수 (Render 등)
- [ ] 사용자 안내: 참고 PDF vs 정식 발행 구분
- [ ] 업체 이메일·사업자번호 등록 매뉴얼

## 5. 작업 순서 한눈에

```
ASP 선택·계약
  → 필수 데이터·발행 단위 확정
  → DB(발행 이력) 설계
  → 서버 ASP 연동 + API
  → 모달(발행 전/후) + 발행 내역 페이지
  → 테스트·운영 배포
```

## 8. 화면·메뉴 배치 의견

| 위치 | 역할 |
|------|------|
| 세금계산서 발부 (현재) | 기간 조회, 업체 선택, **이번 건 발행** |
| 세금계산서 발행 내역 (신규) | 과거 건 조회, 재출력, 취소 |
| 모달 | 발행 전 검토 / 발행 후 승인번호·정식 PDF |

모달에 모든 기능을 넣지 않고, **발행 내역은 별도 페이지**로 분리하는 것을 권장합니다.

## 9. 추후 확정이 필요한 질문

1. 사용할 **ASP**(바로빌, 팝빌, 더존 Smart A 등)는 무엇인가?
2. **발행 단위**: 업체·기간 1장 vs 거래명세서 1건 1장?
3. **1차 목표**: ASP 완전 연동 vs 홈택스용 파일 다운로드만?

위 항목이 정해지면 API 상세·DB 필드·모달 버튼 목록을 구체화할 수 있습니다.
